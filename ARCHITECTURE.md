# Архитектура

## Принципы

- **Статика по умолчанию.** `output: 'static'` — дешёвый хостинг, нет серверной части.
- **Слои с явными границами.** Переиспользуемый стартер отделён от данных проекта.
- **Один код — несколько хостингов.** `site`/`base` вычисляются из `DEPLOY_TARGET`.
- **Интеграции через контракты.** Точки расширения описаны типами, реализации
  подключаются без переписывания страниц.

## Слои

```
┌──────────────────────────────────────────────────────────┐
│ src/pages/            маршруты (тонкие: собирают компоненты) │
├──────────────────────────────────────────────────────────┤
│ src/layouts/          документ: meta, robots, canonical     │
│ src/components/ui/    базовые компоненты (Container, Icon…) │
├──────────────────────────────────────────────────────────┤
│ src/site/             ПРОЕКТ: content, config, components   │
├──────────────────────────────────────────────────────────┤
│ src/lib/              переиспользуемая логика без UI        │
│   paths.ts            withBase(): безопасные URL под base   │
│   deploy/resolve.ts   DEPLOY_TARGET → { site, base }        │
│   site.ts             контракт SiteConfig                   │
│   integrations/       форма обратной связи, Backend API     │
│ src/config/features.ts  флаги из PUBLIC_* переменных         │
│ src/styles/global.css   Tailwind 4 + дизайн-токены (@theme) │
└──────────────────────────────────────────────────────────┘
```

Правило зависимостей: `pages → layouts/components → site → lib`.
`lib/` не импортирует ничего из `site/`, `components/`, `pages/`.

## Маршруты

| URL                                                   | Файл                                                          |
| ----------------------------------------------------- | ------------------------------------------------------------- |
| `/`                                                   | `pages/index.astro` — сайт (`site/components/HomePage.astro`) |
| `/design/`, `/design/{cinematic,editorial,creative}/` | `pages/design/…` — редирект на `/` (`layouts/RedirectLayout`) |
| (любой другой)                                        | `pages/404.astro`                                             |

Старые адреса концепций отправлялись клиенту, поэтому остаются рабочими:
статическая страница с `meta refresh` (работает без JS) плюс `location.replace`,
сохраняющий `#якорь`; `noindex`, `canonical` → главная. Список — `src/site/redirects.ts`.
Редирект-страница не грузит CSS/JS — грузить нечего, переход мгновенный.

## Дизайн «Кадр»

Клиент выбрал концепцию «Кадр» из трёх; «Склейка» и «Рапид» удалены. Сайт —
одна страница: первый экран → шоурил → работы → услуги → обо мне → контакты.
Аудитория приходит по рекомендации или с YouDo и хочет посмотреть работы до
того, как писать, поэтому без попапов, срочности и лишних продающих блоков.

- **Мир:** сетка видоискателя — трети на первом экране (десктоп), угловые метки
  вокруг кадров, поля безопасной зоны (`env(safe-area-inset-*)`). Один шрифт — Onest.
- **Цвет (по отзыву Анны):** белый фон; крупные жирные заголовки, кадры и
  главные действия — ярко-синие (`volt` `#1A2BFF`); основной текст и пояснения —
  чёрные (`pitch`). Токены — `src/styles/global.css`.
- **Работы:** «контактный лист» с номерами кадров и синими метками видоискателя;
  фильтр по категориям (активная — синяя в метках). Под каждой работой —
  услуги, которые делала Анна, обведённые синей «пером» петлёй (из «Склейки»).
  Петля — отдельный `aria-hidden` элемент, а не `::before`: тест измеряет, что
  она охватывает подпись, не задевает соседние и не обрезается (320–1440 px).
- **Действия:** «Обсудить проект» (сплошная синяя) ведёт к контактам,
  «Смотреть шоурил» (синий контур) — к разделу шоурила.
- **Компоненты:** `src/site/components/` — `SiteLayout`, `SiteHeader`, `Hero`,
  `Showreel`, `Work` + `ProjectCard`, `Services`, `About`, `Contact`,
  `SiteFooter`; общий стиль — `src/site/kadr.css`.

Общие механики — в `src/lib/ui/` (`menu.ts`, `filter.ts`; `dialog.ts`,
`header.ts` — для будущих страниц) и `src/components/ui/` (`FootageFrame`,
`PlaceholderTag`, `Icon`, `FontFaces`). Полноэкранное меню помечено
`data-menu-modal`: пока оно открыто, остальная страница получает `inert`.
Якорные переходы учитывают высоту шапки через `scroll-padding-top`.
На телефоне все кнопки и ссылки — не меньше 44×44 px (`tests/e2e/mobile.spec.ts`).
Движение — только отклик на действие (плавная прокрутка, «наведение фокуса»
меток над плеером) и только при `prefers-reduced-motion: no-preference`.

## Содержимое и заглушки

- Всё содержимое — `src/site/content.ts` (типы — `src/lib/portfolio.ts`);
  как заменить — README.md, «Замена контента».
- Факты из брифа: имя, профессия, четыре услуги. Всё остальное — заглушки с
  флагом `placeholder: true` и видимой меткой «Заглушка» (`PlaceholderTag`,
  `data-placeholder`). Это проверяют unit- и E2E-тесты.
- Нельзя выдумывать клиентов, отзывы, награды и цифры. Отзыв без `placeholder`
  обязан иметь автора и компанию; контакт без `href` — заглушка и не ссылка.
- Медиа-слот (`mediaState()`): есть `video` → плеер с controls; есть `poster` →
  картинка; нет ничего → метка «Заглушка». Пустых плееров и кнопок-пустышек нет.
- Позиционирование: Анна прежде всего видеограф (съёмка, монтаж, озвучка);
  съёмка путешествий — новое направление среди услуг, без готовых проектов.
- Демо-проекты вымышлены: над работами стоит `DEMO_WORK_NOTE`, у каждого —
  «Заглушка: вымышленный проект». Сторонние медиа не используются.
- Метаданные — `src/site/site.config.ts`: русский `<title>` и description,
  Open Graph + Twitter card с `public/og.png` (1200×630), иконки `favicon.svg`,
  `favicon.ico`, `apple-touch-icon.png` (`pnpm brand:images`), JSON-LD `Person`
  только из фактов `content.ts`. Индексация включается `PUBLIC_SITE_INDEXABLE=true`.

## Шрифты

Самохостинг, без CDN: файлы из `@fontsource-variable/*` попадают в сборку как
ассеты. Правила (`src/lib/fonts.ts`, наборы — `src/site/fonts.ts`):

- только WOFF2, `font-display: swap`;
- только подмножества **cyrillic** + базовая **latin** (цифры, пунктуация,
  « » —); каждое — отдельный файл с `unicode-range`, браузер качает файл,
  только если на странице есть его символы;
- одно семейство — Onest (OFL-1.1, wght 100–900; ё/й/ъ проверены);
- один `preload` — кириллический файл (им набран h1);
- у Onest локальные fallback-шрифты с метриками (`size-adjust`,
  `ascent/descent/line-gap-override`) по диапазонам весов: обычный, средний,
  полужирный, жирный. Значения откалиброваны в браузере на Windows и Linux
  (середина между ними), первичный расчёт — `pnpm fonts:metrics`. Не меняйте их
  без проверки на обеих ОС — см. TESTING.md.

Вес шрифтов: ~49 КБ (кириллица + латиница). Строки, которые почти ровно
заполняют ширину, переносятся по-разному с fallback и с Onest — такие места
вёрстка разводит намеренно (явный перенос, запас ширины), а подписи-«петли»
набраны весом 600, где fallback совпадает с Onest точнее всего.
Измерения в `ch` зависят от шрифта и меняются при подмене fallback → длина строк
задана в `em`.

## Deploy targets

`astro.config.ts` вызывает `resolveDeployConfig()` (`src/lib/deploy/resolve.ts`):

| `DEPLOY_TARGET` | site / base по умолчанию                               | Кто задаёт            |
| --------------- | ------------------------------------------------------ | --------------------- |
| `local`         | `http://localhost:4321` / `/`                          | по умолчанию          |
| `github-pages`  | `siteConfig.deploy.githubPagesUrl` → `/anna-portfolio` | CI: `configure-pages` |
| `timeweb`       | `siteConfig.deploy.timewebUrl` или `SITE_URL` / `/`    | CI: vars окружения    |

`SITE_URL` и `BASE_PATH` из окружения имеют приоритет. Все внутренние URL строятся
через `withBase()`, поэтому смена `base` не ломает CSS, JS, изображения и ссылки
(проверяется E2E со специально нестандартным base `/base-path-check`).

## Конвейер доставки

`src/lib/delivery/` — без зависимостей, исполняется `node` в GitHub Actions
(`scripts/delivery/run.ts`); подробности и модель доверия — [DELIVERY.md](DELIVERY.md).

| Модуль            | Роль                                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------------------- |
| `policy.ts`       | чистые правила: одобрение, запись `delivery/approval`, CI-вердикт, merge gate, promotion, sync, очистка |
| `approve.ts`      | `issue_comment`: `/publish-approve <sha>` → запись одобрения → merge, если CI уже зелёный               |
| `merge.ts`        | merge gate: перечитать PR, одобрение, комментарий, CI → merge с `sha` (squash)                          |
| `workflow-run.ts` | `workflow_run` (CI завершён) → merge gate для PR этого прогона                                          |
| `promote.ts`      | promotion `dev → main` и sync `main → dev`                                                              |
| `cleanup.ts`      | удаление смёрженных конвейером `feature/*` веток                                                        |
| `live.ts`         | live smoke после деплоя Pages                                                                           |
| `rest.ts`         | GitHub REST/GraphQL, токен App, read-only CI-клиент (`GITHUB_TOKEN`)                                    |
| `testing.ts`      | in-memory GitHub для тестов (не импортируется в рабочий код)                                            |

Решения — в чистых функциях, ввод-вывод — через интерфейсы `GitHubApi`/`CiApi`,
поэтому каждое правило безопасности покрыто unit-тестом.

## Точки интеграции

Сайт статический, поэтому всё, что требует секретов, выполняется **на бэкенде**.
Браузер знает только публичный URL API.

```
 Браузер (форма)                Backend API (будущий)            Внешние сервисы
 ┌──────────────┐  POST /leads  ┌───────────────────────┐        ┌───────────┐
 │ LeadService  │──────────────▶│ валидация, антиспам,  │──────▶ │ Telegram  │
 │ validateLead │  JSON         │ rate-limit, секреты   │──────▶ │ CRM       │
 └──────────────┘               └───────────────────────┘──────▶ │ e-mail    │
   PUBLIC_API_BASE_URL                TELEGRAM_BOT_TOKEN…          └───────────┘
```

| Интеграция     | Где в коде (frontend)                                                         | Статус                     |
| -------------- | ----------------------------------------------------------------------------- | -------------------------- |
| Анкета / форма | `lib/integrations/lead.ts` (валидация, honeypot), `lead-service.ts`           | контракт + тесты, UI нет   |
| Backend API    | `lib/integrations/http-channel.ts` (`POST {API}/leads`, таймаут, коды ошибок) | готов к подключению        |
| Telegram-бот   | только на бэкенде (секрет `TELEGRAM_BOT_TOKEN`)                               | не реализуется во frontend |
| CRM            | только на бэкенде; во frontend — тот же `LeadChannel`                         | не реализуется во frontend |
| Включение      | `config/features.ts`: `features.leadForm = Boolean(PUBLIC_API_BASE_URL)`      | выключено                  |

Контракт `LeadChannel` (`types.ts`) позволяет подключить другой транспорт
(например, сервис форм) без изменения страниц: `createLeadService({ channel })`.

Рекомендуемый бэкенд, когда понадобится: одна serverless-функция
(Timeweb Cloud Functions или аналог) с эндпоинтом `POST /leads`, принимающая
`LeadInput` без поля `website`, отвечающая `201 {id}` / `422` / `5xx`.
БД не нужна, пока лиды уходят в Telegram/CRM.

## Дизайн-система

`src/styles/global.css` содержит токены в `@theme` (Tailwind 4 генерирует из них
утилиты `bg-paper`, `text-volt`, `text-pitch`, `font-kadr`, `max-w-page` и т. д.):
базовые нейтральные (стартер) и токены сайта («Кадр»). Компоненты не используют
«сырые» цвета.

## Использование как шаблона

1. Settings → General → **Template repository**.
2. Новый репозиторий: **Use this template**.
3. Отредактировать `src/site/site.config.ts` (имя, метаданные, URL хостингов),
   `src/site/content.ts` (контент) и `src/site/components/` (вёрстка сайта).
4. Обновить `src/pages/*`, `src/site/redirects.ts` и `tests/e2e/routes.ts`.
5. Обновить `package.json` (`name`, `description`) и `README.md`.
6. Включить Pages (Source: GitHub Actions) и rulesets — см. DEPLOYMENT.md.
7. По желанию — автоматическая доставка одобренных изменений: свой GitHub App
   и переменные `DELIVERY_*` — см. DELIVERY.md («Перенос в другой проект»).

Ничего в `src/lib/`, `src/components/ui/`, `src/layouts/`, `.github/`, `tests/`
не содержит данных конкретного клиента.
