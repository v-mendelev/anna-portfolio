## Сборка веб-версий

`pnpm media:build` (нужен ffmpeg в `PATH` или в переменной `FFMPEG`) читает
`scripts/media-manifest.mjs` и пишет в `public/media/<ключ>/`:

- `video.mp4` — H.264 High, yuv420p, 720 px по короткой стороне (вертикаль
  720×1280, горизонталь 1280×720 / 864×540 для 16:10), CRF 27 с потолком
  1,4 Мбит/с, частота кадров исходника (≤ 30), AAC 96 кбит/с стерео,
  `+faststart`. Без обрезки кадра: соотношение сторон исходника сохраняется.
- `poster.webp` — вручную выбранный кадр (не переход, не титр), размер видео.
- `hero/still.avif` + `still.webp` — кадр интро подкаста 0:32 (работа Анны),
  16:9, 1600 px.

Кадры для постеров и hero выбираются вручную: без детей и только из
собственных работ Анны. Начало шоурила (0:00–0:09: клавиатура, кроссовки,
танцовщица, глаз в маске, операционная) похоже на сток, поэтому как
отдельный кадр не используется.

< 12 МБ, картинка < 300 КБ, всего < 90 МБ.

до нажатия «play» грузится лишь постер; ничего не играет само (автоплея нет,
так что reduced motion соблюдается), одновременно играет одно видео, карточка,
скрытая фильтром, ставится на паузу.

## Хранение медиа: GitHub Pages (staging) и Timeweb (production)

Контент ссылается на медиа **ключами** (`work/fashion/video.mp4`), а не URL.
Корень задаёт `src/lib/media.ts`:

- без переменной — `public/media/` (локальный просмотр);
- `PUBLIC_MEDIA_BASE_URL=https://<хранилище>/portfolio/v1/` — тот же ключ
  из внешнего хранилища.

### Рекомендуемая схема

```
media-src/ (оригиналы, только локально и в архиве у Анны)
   │  pnpm media:build <папка>      ← воспроизводимо из оригиналов
   ▼
S3-бакет Timeweb Cloud  ── portfolio/v1/<ключ>  (публичное чтение)
   │            └─ CDN Timeweb (production)
   ├──▶ GitHub Pages (staging): PUBLIC_MEDIA_BASE_URL = адрес бакета
   └──▶ Timeweb (production):   PUBLIC_MEDIA_BASE_URL = адрес CDN
Git: код, манифест, ключи — без видео
```

1. **Одно внешнее хранилище для обоих сайтов** — S3-совместимое хранилище
   Timeweb Cloud (production всё равно будет в Timeweb; данные в РФ, близко к
   аудитории). Бакет с публичным чтением только на префикс `portfolio/`.
2. **Версии в ключе:** `portfolio/v1/...`. Файлы неизменяемы:
   `Cache-Control: public, max-age=31536000, immutable`,
   `Content-Type: video/mp4` / `image/webp` / `image/avif`. Новая сборка —
   новый префикс (`v2`), старый удаляется после переключения.
3. **Staging (GitHub Pages)** берёт медиа из бакета напрямую (CORS для
   `<video src>` не нужен), **production** — через CDN Timeweb. Сайт и
   сборка от этого не зависят: меняется одна переменная окружения.
4. **Неодобренные материалы** не загружаются в публичный бакет: сначала
   ответы Анны (CONTENT-REVIEW.md), потом загрузка.
5. **Загрузка** — вручную владельцем (`aws s3 sync <папка> s3://…/portfolio/v1/
--endpoint-url <endpoint Timeweb>`); автоматизация в CI — отдельно и
   только после согласования (это изменение CI/CD и секретов).
6. **Объём и стоимость:** ~75 МБ сейчас, ~200–250 МБ с HD-версиями
   (1080 px). Основная статья — исходящий трафик; цену уточнить по
   тарифу Timeweb. Ничего платного не создано.
7. **Оригиналы** — не в Git и не в публичном бакете: в `media-src/` и в
   архиве Анны; `_yandex-inventory.json` хранит md5 для сверки.

Временные ссылки Яндекс Диска (`downloader.disk.yandex.ru/...`) как источник
видео **не используются**: они истекают и не рассчитаны на раздачу сайта.

### План: убрать видео из Git до первого push

Сейчас 3 локальных коммита (`635ea75`, `dda5816`, `25a3e88`) — ветка нигде
не опубликована. Коммит `dda5816` содержит 22 файла медиа (≈ 77 МБ, из них
10 MP4). Так как push ещё не было, «чистка истории» — это просто пересборка
этих коммитов, без `filter-repo` и без переписывания чужой истории:

1. Резервная ветка: `git branch backup/real-portfolio-media-binaries`.
2. `git reset --soft origin/dev` — все изменения остаются в рабочей копии.
3. В `.gitignore` добавить `public/media/`; `git rm -r --cached public/media`.
4. Сделать код независимым от наличия файлов:
   - unit-тест бюджета проверяет файлы только если они собраны, а
     согласованность «ключи в content.ts = ключи из манифеста» —
     всегда, без файлов;
   - E2E в CI собирает тестовые медиа сами: `pnpm media:build` недоступен
     (нет оригиналов), поэтому глобальная настройка Playwright генерирует
     короткие синтетические ролики/постеры по тем же ключам (ffmpeg
     `testsrc`) — без изменения workflow.
   - без `PUBLIC_MEDIA_BASE_URL` и без файлов сайт показывает постеры как
     заглушки «видео появится», а не битый плеер.
5. Закоммитить заново тремя коммитами, `pnpm verify`.
6. Проверка перед push:
   `git rev-list --objects origin/dev..HEAD | git cat-file --batch-check | grep -E "\.(mp4|mov|webp|avif)"`
   — пусто; `git count-objects -vH` — без десятков МБ.
7. Удалить резервную ветку и `git gc --prune=now` — только после того, как
   медиа лежат в бакете.

Пункты 4 и 5 — изменения кода, их делать после выбора хранилища.

## Права на публикацию

До публикации (merge в `main` или push ветки — репозиторий публичный)
нужно подтверждение Анны, что:

- заказчики разрешают показывать ролики в портфолио;
- есть согласия людей в кадре, особенно детей (танцевальные ролики, IDC) и
  врачей / участников конференции;
- музыка в роликах может звучать на сайте (лицензии на треки);
- сторонние фрагменты в шоуриле (если есть сток) лицензированы для такого
  использования.
