# CLAUDE.md — правила разработки

Этот файл читают Claude Code и другие ИИ-агенты, а также люди. Правила обязательны.

## Проект

Статический сайт на Astro 7 + TypeScript strict + Tailwind CSS 4, pnpm.
Хостинг демо — GitHub Pages (подпуть `/anna-portfolio/`), в будущем — Timeweb Cloud.
Разработка ведётся на нативной Windows (PowerShell), CI — Linux + Windows.

## Обязательные правила

1. **Не ломать работающее поведение.** Изменения должны сохранять существующие
   маршруты, URL, тестовые идентификаторы (`data-testid`) и контракты в `src/lib/`.
   Если поведение нужно изменить — явно опиши это и обнови тесты осознанно.
2. **Писать тесты на новую функциональность.** Логика в `src/lib/` — unit-тесты
   (Vitest, рядом с файлом `*.test.ts`). Новые страницы/маршруты — добавить в
   `tests/e2e/routes.ts` (smoke + адаптивность покрываются автоматически).
   Не писать фиктивные тесты ради зелёного CI.
3. **Выполнять регрессию перед завершением задачи:** `pnpm verify`
   (typecheck, lint, format, unit, build, E2E). Задача не завершена, пока он не зелёный.
4. **Не усложнять архитектуру без причины.** Никаких новых фреймворков, state-менеджеров,
   бэкенда, БД или CMS без явной необходимости и согласования.
5. **Соблюдать модульность.** Проектно-специфичное — только в `src/site/`.
   Переиспользуемое — в `src/lib/`, `src/components/ui/`, `src/layouts/`.
   Общая инфраструктура не должна ссылаться на конкретные тексты и данные клиента.
6. **Не добавлять персональные данные в логи.** Никаких `console.log` с данными форм,
   контактами, именами (ESLint запрещает `console.log`). Ошибки — без значений полей.
7. **Не публиковать секреты.** Токены, ключи, пароли — только в GitHub Secrets /
   окружении хостинга. В браузер попадают только `PUBLIC_*` переменные — секреты
   туда не класть. `.env` не коммитится; шаблон — `.env.example`.
8. **Учитывать мобильные устройства.** Mobile-first. Проверять ширины
   320, 360, 375, 390, 393, 414, 430, 768, 1024, 1440, 1920 px (это делает
   `tests/e2e/responsive.spec.ts`). Без горизонтального скролла, тап-цели ≥ 16 px.
9. **Соблюдать существующую дизайн-систему.** Цвета, шрифты, ширины — только через
   токены из `src/styles/global.css` (`bg-surface`, `text-ink`, `max-w-page`, …).
   Новые токены добавлять в `@theme`, а не хардкодить значения в компонентах.

## Технические правила

- Внутренние ссылки и пути к ассетам из `public/` — **только через `withBase()`**
  (`src/lib/paths.ts`). Хардкод `/path` ломает GitHub Pages; E2E это ловят.
- `trailingSlash: 'always'`: все внутренние URL заканчиваются на `/`.
- Интеграции (форма, Telegram, CRM, Backend API) — через контракты
  `src/lib/integrations/`. Telegram/CRM вызываются только с бэкенда, не из браузера.
- Команды и скрипты должны работать в нативной Windows: в `package.json` можно
  писать `VAR=value cmd` (включён `shellEmulator` в `pnpm-workspace.yaml`),
  но не использовать bash-специфичный синтаксис (`&&` допустим, `$(...)`, `rm -rf` — нет).
- TypeScript strict + `noUncheckedIndexedAccess`; не использовать `any` и `!`.
- Перед коммитом: `pnpm format`. Коммиты небольшие, сообщения по смыслу.

## Ветки и релизы

- `feature/*` → PR в `dev` → PR `dev` → `main`. Прямые пуши в `main` запрещены.
- `main` автоматически публикуется на GitHub Pages после зелёного CI.
- Откат — см. DEPLOYMENT.md (re-deploy предыдущего SHA или `git revert`).

## Что не делать без согласования

- Менять CI/CD, rulesets, deploy-конфигурацию.
- Добавлять зависимости (особенно runtime) и внешние скрипты/CDN.
- Подключать платные сервисы, аналитику, трекеры.
