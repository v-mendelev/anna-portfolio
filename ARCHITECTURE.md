# Архитектура

## Принципы

- **Статика по умолчанию.** `output: 'static'` — дешёвый хостинг, нет серверной части.
- **Слои с явными границами.** Переиспользуемый стартер отделён от данных проекта.
- **Один код — несколько хостингов.** `site`/`base` вычисляются из `DEPLOY_TARGET`.
- **Интеграции через контракты.** Точки расширения описаны типами, реализации
  подключаются без переписывания страниц.

## Слои

```
┌──────────────────────────────────────────────────────────┐
│ src/pages/            маршруты (тонкие: собирают компоненты) │
├──────────────────────────────────────────────────────────┤
│ src/layouts/          документ: meta, robots, canonical     │
│ src/components/ui/    базовые компоненты (Container, Icon…) │
│ src/components/demo/  три дизайн-концепции                  │
├──────────────────────────────────────────────────────────┤
│ src/site/             ПРОЕКТ: site.config.ts, demos.ts      │
├──────────────────────────────────────────────────────────┤
│ src/lib/              переиспользуемая логика без UI        │
│   paths.ts            withBase(): безопасные URL под base   │
│   deploy/resolve.ts   DEPLOY_TARGET → { site, base }        │
│   site.ts             контракт SiteConfig / DemoVariant     │
│   integrations/       форма обратной связи, Backend API     │
│ src/config/features.ts  флаги из PUBLIC_* переменных         │
│ src/styles/global.css   Tailwind 4 + дизайн-токены (@theme) │
└──────────────────────────────────────────────────────────┘
```

Правило зависимостей: `pages → layouts/components → site → lib`.
`lib/` не импортирует ничего из `site/`, `components/`, `pages/`.

## Маршруты

| URL                  | Файл                                             |
| -------------------- | ------------------------------------------------ |
| `/`                  | `pages/index.astro` — meta-refresh на `/design/` |
| `/design/`           | `pages/design/index.astro` — выбор демо          |
| `/design/cinematic/` | `pages/design/cinematic/index.astro`             |
| `/design/editorial/` | `pages/design/editorial/index.astro`             |
| `/design/creative/`  | `pages/design/creative/index.astro`              |
| (любой другой)       | `pages/404.astro`                                |

Список демо — `src/site/demos.ts`. Unit-тест `demos.test.ts` гарантирует, что
для каждого демо есть страница и нет «лишних» директорий.

Каждая демоверсия — отдельная папка страниц и свой компонент
`src/components/demo/<slug>/<Name>Page.astro` со своими токенами (`cine-`, `ed-`,
`cr-` в `@theme`), не влияющими на остальные.

## Дизайн-концепции

Все три концепции рендерят **одно и то же содержимое** (`src/site/content.ts`) и
одинаковые якоря секций: `top, showreel, work, services, travel, about, reviews,
contact` (`SECTIONS`). Различаются только визуальный мир и подача.

| Концепция | Мир                                                                                                                                              | Подпись (signature)                                                                                                                  |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| Cinematic | Тёмный зал; цвет только у «плёнки»                                                                                                               | Экран героя отъезжает в зал при скролле (scroll-driven, одно движение); работы с подписями-субтитрами; услуги как финальные титры    |
| Editorial | Современный атлас-монография на холодной бумаге                                                                                                  | Указатель работ: строка раскрывается на месте, на десктопе превью следует за курсором; маршрут съёмки пунктиром                      |
| Creative  | Конструктивистский киноплакат на тёплой слоновой кости: слива — «краска», коралл — сигнал и действие, шалфей — поле (без политической символики) | Шоурил открывается iris-шторкой из кнопки; слова услуг едут по диагональным лентам при скролле; кадр монтажа можно «вытащить» вперёд |

Общие механики — в `src/lib/ui/` (`menu.ts`, `dialog.ts`, `filter.ts`, `header.ts`) и
`src/components/ui/` (`FootageFrame`, `PlaceholderTag`, `Icon`, `FontFaces`).
Полноэкранные меню помечены `data-menu-modal`: пока меню открыто, остальная
страница получает `inert` (фокус и скринридер остаются в меню).
Шапка: `header.ts` ставит `data-scrolled` на `[data-site-header]`, как только под
шапкой начинает проходить контент (или после элемента из `data-solid-after`);
концепция делает шапку непрозрачной, чтобы текст не налезал на имя и меню.
Якорные переходы учитывают высоту шапки через `scroll-padding-top` (`global.css`).
На телефоне все кнопки и ссылки — не меньше 44×44 px (`tests/e2e/mobile.spec.ts`).
Движение: только при `prefers-reduced-motion: no-preference`; при `reduce`
анимаций нет вообще (проверяется E2E через `document.getAnimations()`).

## Содержимое и заглушки

- Факты из брифа: имя, профессия, четыре услуги. Всё остальное — заглушки с
  флагом `placeholder: true`.
- Каждая заглушка в интерфейсе показывает видимую метку «Заглушка»
  (`PlaceholderTag`, атрибут `data-placeholder`). Это проверяют unit- и E2E-тесты.
- Нельзя выдумывать клиентов, отзывы, награды и цифры. Отзыв без `placeholder`
  обязан иметь автора и компанию; контакт без `href` — заглушка.
- Позиционирование: Анна прежде всего видеограф (съёмка, монтаж, озвучка);
  съёмка путешествий — новое направление без готовых туристических проектов.
  Тексты первого экрана — `HERO`, заголовок раздела — `TRAVEL_HEADING`
  (`src/site/content.ts`), проверяются unit- и E2E-тестами.
- Демо-проекты вымышлены: над портфолио каждой концепции стоит пояснение
  `DEMO_WORK_NOTE`, у каждого проекта — видимая метка «Заглушка: вымышленный проект».
- Сторонние медиа не используются: кадры-заглушки рисуются CSS-градиентом
  в «цветовой истории» проекта (`FootageFrame`). Реальный `poster`/`video`
  подставляется теми же полями без изменения вёрстки.

## Шрифты

Самохостинг, без CDN: файлы из `@fontsource-variable/*` попадают в сборку как
ассеты. Правила (`src/lib/fonts.ts`, наборы — `src/site/fonts.ts`):

- только WOFF2, `font-display: swap`;
- только подмножества **cyrillic** + базовая **latin** (цифры, пунктуация,
  « » —); каждое — отдельный файл с `unicode-range`, браузер качает файл,
  только если на странице есть его символы;
- страница грузит только свои начертания: Cinematic — Cormorant italic +
  Commissioner; Editorial — Literata (ось wght, без вдвое более тяжёлой opsz) +
  Golos Text; Creative — Unbounded + Golos Text;
- один `preload` на страницу — кириллический файл шрифта заголовка h1;
- у каждого семейства есть локальный fallback с метриками (`size-adjust`,
  `ascent/descent/line-gap-override`), при необходимости — отдельный для
  светлых/жирных весов и настоящий курсив. Значения откалиброваны в браузере
  на реальных весах; первичный расчёт — `pnpm fonts:metrics`.

Фактический вес шрифтов на странице: 120–139 КБ. Дальнейшее уменьшение
(~40%) возможно только сабсеттингом под реальный текст — это требует
dev-инструмента (например, `subset-font`) и отдельного согласования.

## Deploy targets

`astro.config.ts` вызывает `resolveDeployConfig()` (`src/lib/deploy/resolve.ts`):

| `DEPLOY_TARGET` | site / base по умолчанию                               | Кто задаёт            |
| --------------- | ------------------------------------------------------ | --------------------- |
| `local`         | `http://localhost:4321` / `/`                          | по умолчанию          |
| `github-pages`  | `siteConfig.deploy.githubPagesUrl` → `/anna-portfolio` | CI: `configure-pages` |
| `timeweb`       | `siteConfig.deploy.timewebUrl` или `SITE_URL` / `/`    | CI: vars окружения    |

`SITE_URL` и `BASE_PATH` из окружения имеют приоритет. Все внутренние URL строятся
через `withBase()`, поэтому смена `base` не ломает CSS, JS, изображения и ссылки
(проверяется E2E со специально нестандартным base `/base-path-check`).

## Точки интеграции

Сайт статический, поэтому всё, что требует секретов, выполняется **на бэкенде**.
Браузер знает только публичный URL API.

```
 Браузер (форма)                Backend API (будущий)            Внешние сервисы
 ┌──────────────┐  POST /leads  ┌───────────────────────┐        ┌───────────┐
 │ LeadService  │──────────────▶│ валидация, антиспам,  │──────▶ │ Telegram  │
 │ validateLead │  JSON         │ rate-limit, секреты   │──────▶ │ CRM       │
 └──────────────┘               └───────────────────────┘──────▶ │ e-mail    │
   PUBLIC_API_BASE_URL                TELEGRAM_BOT_TOKEN…          └───────────┘
```

| Интеграция     | Где в коде (frontend)                                                         | Статус                     |
| -------------- | ----------------------------------------------------------------------------- | -------------------------- |
| Анкета / форма | `lib/integrations/lead.ts` (валидация, honeypot), `lead-service.ts`           | контракт + тесты, UI нет   |
| Backend API    | `lib/integrations/http-channel.ts` (`POST {API}/leads`, таймаут, коды ошибок) | готов к подключению        |
| Telegram-бот   | только на бэкенде (секрет `TELEGRAM_BOT_TOKEN`)                               | не реализуется во frontend |
| CRM            | только на бэкенде; во frontend — тот же `LeadChannel`                         | не реализуется во frontend |
| Включение      | `config/features.ts`: `features.leadForm = Boolean(PUBLIC_API_BASE_URL)`      | выключено                  |

Контракт `LeadChannel` (`types.ts`) позволяет подключить другой транспорт
(например, сервис форм) без изменения страниц: `createLeadService({ channel })`.

Рекомендуемый бэкенд, когда понадобится: одна serverless-функция
(Timeweb Cloud Functions или аналог) с эндпоинтом `POST /leads`, принимающая
`LeadInput` без поля `website`, отвечающая `201 {id}` / `422` / `5xx`.
БД не нужна, пока лиды уходят в Telegram/CRM.

## Дизайн-система

`src/styles/global.css` содержит токены в `@theme` (Tailwind 4 генерирует из них
утилиты `bg-surface`, `text-ink-muted`, `max-w-page` и т. д.). Сейчас токены
нейтральные — финальная визуальная система появится при разработке демо.
Компоненты не используют «сырые» цвета.

## Использование как шаблона

1. Settings → General → **Template repository**.
2. Новый репозиторий: **Use this template**.
3. Отредактировать `src/site/site.config.ts` (имя, язык, URL хостингов) и
   `src/site/demos.ts` (или удалить демо и их страницы).
4. Заменить `src/pages/*` под новый проект, обновить `tests/e2e/routes.ts`.
5. Обновить `package.json` (`name`, `description`) и `README.md`.
6. Включить Pages (Source: GitHub Actions) и rulesets — см. DEPLOYMENT.md.

Ничего в `src/lib/`, `src/components/ui/`, `src/layouts/`, `.github/`, `tests/`
не содержит данных конкретного клиента.
